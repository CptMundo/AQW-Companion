# AQW Companion — Alpha 0.9.9.7
Created by CptMundo. Unofficial fan project; not affiliated with Artix Entertainment.

## What is included
- `site/index.html`: complete browser-based Companion, no web server API needed.
- `site/data/companion_database.json`: public catalogue generated by the builder (initially EMPTY; it must not be confused with a real verified item database).
- `builder/build_database.js`: offline converter for community JSON data.
- `.github/workflows/deploy.yml`: GitHub Pages deployment workflow.

## Important privacy and data limitations
**Do not upload** `CptMundo_Inventory_COMPLETO.json`, personal backups, cookies, passwords, or account exports to the public repository. The website stores player inventories and plans in their own browser. Its public item catalogue is loaded from the same-origin static `site/data/companion_database.json` when populated.

This initial package does **not** bundle or automatically scrape community datasets. Obtain reuse permission and keep source credits/terms. The builder imports only JSON files you place in `builder/source/`. Incomplete or unknown requirements must remain unknown; verify important quests/recipes in AQWWiki.

## Publish online (beginner steps)
1. Create a **new public repository** on GitHub named `aqw-companion` (any name is fine).
2. Unzip the release, and upload the *contents* of this folder to the repository, preserving `.github/workflows/deploy.yml` and `site/index.html`. Do not upload an enclosing `AQW_Companion_Web_Alpha_0.9.9.7` folder only.
3. In repository **Settings → Pages → Build and deployment → Source**, choose **GitHub Actions**.
4. Open **Actions → Deploy AQW Companion** to watch the status; GitHub will provide the site URL in the deployment result.
5. The normal project URL follows `https://YOUR-GITHUB-USERNAME.github.io/aqw-companion/` after the deployment succeeds.

If the browser's local file version already has projects/inventory, first use **Backup**, then import the backup in the new hosted site. `file://` and `https://` are different origins: they do not automatically share local storage.

## Prepare the database
1. Read `builder/source/README.txt` about the five expected files.
2. Put the community JSON files in `builder/source/` after checking licensing/redistribution terms.
3. In a terminal with Node.js installed, run: `node builder/build_database.js builder/source site/data/companion_database.json`
4. Check `site/data/build_report.json` and compare sample recipes against their wiki pages.
5. Upload the updated database and report to GitHub; the deployment workflow updates the site automatically on each push to `main`.

The builder is a first-pass importer. It handles a subset of community formats, so unknown and alternative acquisition routes may be incomplete; it should not be treated as a fully validated quest graph.

## Future automation
The deployment is automatic on every commit to `main`. **New AQW data is not fetched automatically yet.** For that, we need a legally permitted source feed, a validation pipeline, and change review before publishing updated metadata.
